# 2.18.d — File-Based Routing in Next.js

> **In one sentence:** URLs map to the `app` directory tree; special files add layouts, loading states, and HTTP handlers—convention replaces a central route configuration file.

**Navigation:** [← Setting Up](./2.18.c-Setting-Up-a-NextJS-Project.md) · [Next → Layouts](./2.18.e-Layouts-in-NextJS.md)

---


## 1. File-based routing in the App Router

The URL path is derived from the **folder tree** under `app/`:

```
app/page.tsx           → /
app/about/page.tsx     → /about
app/blog/[slug]/page.tsx → /blog/:slug
```

**Special files** (non-routes) coexist: `layout.tsx`, `loading.tsx`, `error.tsx`, `route.ts`, etc.

### 1.1 Route groups `(folder)`

Folders wrapped in parentheses **do not** appear in the URL — useful for organizing marketing vs app surfaces.

### 1.2 Dynamic segments

`[id]`, `[...slug]`, `[[...optional]]` — param shapes differ; always validate and return `notFound()` when invalid.

### 1.3 Colocation

You may place non-route modules beside routes when using private folders or structured `components/` trees—pick a team rule and keep imports tidy.

### 1.4 Middleware

`middleware.ts` runs **before** rendering for matched paths — auth redirects, A/B, geo headers.
