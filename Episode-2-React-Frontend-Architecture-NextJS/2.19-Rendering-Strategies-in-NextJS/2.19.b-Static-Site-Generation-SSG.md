# 2.19.b — Static Site Generation (SSG)

> **In one sentence:** SSG precomputes pages so the runtime path is mostly CDN-fast static delivery—ideal for stable public content until scale or freshness forces ISR or SSR.

**Navigation:** [← SSR](./2.19.a-Server-Side-Rendering-SSR.md) · [Next → ISR](./2.19.c-Incremental-Static-Regeneration-ISR.md)

---


## 1. What “Static Site Generation” Means

SSG means HTML (and RSC payload where applicable) is produced **at build time** (`next build`) or otherwise **precomputed**, then served as **static files** or from a **CDN** with high cache hit rates. Each visitor receives the **same bytes** for a given URL — unless you add **ISR**, **middleware rewrites**, or **client-side personalization**.

### 1.1 Why SSG is fast

The request path is:

```
CDN edge → static asset (HTML/JSON) → browser
```

No database on the critical path for the happy path. **TTFB** can approach a few tens of milliseconds globally when cached.

### 1.2 `getStaticProps` mental model (Pages Router)

```tsx
export async function getStaticProps() {
  const posts = await loadAllPosts();
  return { props: { posts }, revalidate: false };
}
```

**Interview:** "Static" implies **predictable content** at build. If content changes often, pure SSG without ISR becomes a **deploy bottleneck**.

### 1.3 App Router static generation

Use `generateStaticParams` to enumerate dynamic routes to prebuild. For fully static marketing pages, omit dynamic APIs entirely and allow default static behavior per Next version docs.

### 1.4 SEO benefits and limits

SSG is excellent for **stable** content: blogs, docs, landing pages. If **auth-gated** content is accidentally statically generated, you leak data — always verify **segment static vs dynamic** behavior.

### 1.5 Build-time scale

| Posts | Build cost |
| ----- | ---------- |
| 100 | trivial |
| 10,000 | CI minutes matter |
| 1,000,000 | need partial static + ISR/on-demand |

### 1.6 Export mode (`output: 'export'`)

Fully static hosting (S3/CloudFront) — **no** Route Handlers, **no** ISR as traditionally implemented on Vercel serverless. Interviewers may ask: know the constraints.

### 1.7 Pairing with client hydration

Static HTML can still **hydrate** rich components. The static part is the **initial** snapshot; client state can diverge after mount.

### 1.8 Checklist

- [ ] No secrets in static HTML
- [ ] Canonical URLs and meta tags validated at build
- [ ] 404/410 behavior for removed content
